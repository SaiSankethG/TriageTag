How to use the Issue Triage Assistant

A two-minute guide for maintainers: what the assistant does, how to read a report, and what stays private.

What it does

When someone opens an issue in your repository, the assistant prepares a short note for the maintainers, usually within a few seconds:

  • Similar earlier issues: the three earlier issues that look most like the new one, each with a similarity score.
  • Details the reporter gave: whether the issue has a version, steps to reproduce, expected vs actual behaviour, and logs.
  • Already fixed?: if a very similar issue was fixed, in which version, compared with the reporter's version.
  • Suggested labels: labels that similar issues had.
  • A draft reply: a short first answer that links only to your own documentation and earlier issues. You edit it before posting.

How to read a report

  1. Start with the coloured box at the top. It answers "is this a duplicate?" in words:
    BoxMeaningWhat to do
    Likely duplicateVery similar (90%+) and the AI check agrees it is the same problem.Open the match; close as duplicate if it fits.
    Possible duplicateSimilar (75%+), or very similar but the AI check isn't sure.Have a look at the match before answering.
    Probably not a duplicateNothing earlier is close enough.Triage it as a new issue.
  2. Check the similar issues. The bar shows how close each one is. The tag next to it says whether that issue is open or how it was closed (fixed, not planned, duplicate). A yellow "Already fixed?" box appears when the best match was fixed in a release.
  3. Look at "Details the reporter gave". ✓ = given, ✗ = missing (worth asking for), – = not needed for this kind of issue.
  4. Use the draft reply if it helps. Press Copy reply, paste it into GitHub, and edit it. Its sources are listed under it.

Finding an issue on this page

  • With a report (left side): the newest issues the assistant has looked at.
  • All issues: every stored issue, with a search by title.
  • Issue number: type it at the top left and press Open.
  • Every report has its own link (?repo=…&number=…), so you can share it.

What is private, what is public

  • It only reads public issues and your public documentation.
  • By default it never posts anything on GitHub (shadow mode). Reports are only on this page.
  • A maintainer can switch on comment mode for one repository. Then the assistant posts at most one comment per issue, only for issues from outside the team, and only when the match is 90%+ and the AI check agrees. The comment says that a bot suggested it.
  • Creating new reports on this page needs an admin token, so visitors can't run up costs.

How good is it?

Measured on Spring Boot's history, on 833 issues that maintainers closed as duplicates, each searched as if it had just been opened: the real original is in the top 3 for 46% of them (keyword search: 26%) and in the top 10 for 61%. It is a helper, not a judge: duplicates are rare, so a high score alone is often wrong. That's why it is private by default.
