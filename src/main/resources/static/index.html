Less time sorting issues, more time fixing them

      

        

          
Finds the issue it duplicates

          
The new issue is compared by meaning with every earlier issue in the repository, so a different wording still matches.

          
On 833 real Spring Boot duplicates, the original was in its top 3 for 46%. Keyword search found 26%.

        

        

          
Says what the reporter left out

          
Version, steps to reproduce, expected and actual behaviour, logs. You see at once what to ask for.

          
Items that don't apply, like steps for a feature request, are marked as not needed.

        

        

          
Drafts the first reply

          
A short answer built from your own documentation and earlier issues, with links. You edit it before posting.

          
If nothing relevant is found, there is no draft instead of a guess.

        

        

          
Tells you when it's already fixed

          
If a very similar issue was fixed in a release, the note says which one, and whether the reporter is on an older version.

          
This comes from GitHub's own records, not from the AI.
